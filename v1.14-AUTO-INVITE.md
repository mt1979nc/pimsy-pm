# v1.14 Auto customer invite

PATH emails a portal invite when a customer/site is set up or a contact is added
for portal access. Staff no longer need a separate “remember to invite” step on
the common path. **Hold from live until Alexander ships.**

**Version:** 1.14.1 (`APP_VERSION` / `package.json`). Main already shipped **v1.14.0** (any-specialist access).

PATH + Prism naming is unchanged. No schema migrate. No playbook resync. Dock
WIP import and Prism import still never create contacts or send invites.

## What triggers an invite

| Event | What happens |
|-------|----------------|
| **New customer** with Portal contact name + work email | Provisions a `CUSTOMER` user pinned to that account and sends the PATH invite. |
| **New project** (non-internal, portal on) | Optional new Portal contact is provisioned, added to the project, and invited. Existing account contacts are added as `CUSTOMER_CONTACT` and invited only if they still need one. |
| **Customer portal enabled** flipped on in project Settings | Same as site-ready: account contacts are added to the project and invited if needed. |
| **Invite contact** on the customer page or project Settings | Same provision + invite helper (the form is no longer a different email path). |
| **Add an existing contact** to a portal-enabled project | Membership is added; invite sends only if they have not signed in and have no pending invite. |

Empty portal-contact fields on create are fine — the customer/project is still created; invite happens when a contact is added later.

## How re-invite works

Auto-send is **idempotent**:

- Pending unused set-password token that has not expired → skip (do not spam).
- Contact has signed in (`lastSeenAt`) or already set a password → skip.
- Unused token expired and they never signed in → send again (they never got in).
- Staff **Resend invite** on the contact row (or `resend=1` on the invite form) **force**-mints a new token (old unused tokens are cleared) and emails it.

Staff still get a copyable invite URL after a new send (and when Resend is not keyed, after a local `PASSWORD-RESET-LINK.txt` write).

## Auth boundary

Customer portal users are **not staff**.

- Addresses on `INTERNAL_EMAIL_DOMAINS` (default `pimsyehr.com`) and the bootstrap owner email cannot be provisioned as `CUSTOMER`.
- An existing staff user at that address is refused (“belongs to an internal staff account”).
- Sign-in still allows unprovisioned internal-domain addresses to become `SPECIALIST` (unchanged).

## Email

Existing Resend path (`src/lib/email.ts` `customerInviteEmail` + `sendEmail`). Subject: `You're invited to PATH — {practice}`. Footer tells them never to post patient information. No PHI in templates or tests.
