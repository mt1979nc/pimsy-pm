# v1.9 Playbook, optional areas, staffing — implementation report

**Date:** 2026-09-11  
**Branch:** `cursor/v1.9-playbook-staffing-d390`  
**Version:** 1.9.0  
**Prism forecast:** still out of scope (later). This 1.9.0 is Alexander Morse’s playbook / N/A / chooser / staffing slice.

## What shipped

1. **Fully editable templates** — `/templates/[id]` add/remove tasks and phases; HTML5 drag-and-drop reorder for phases and tasks. Live projects are not rewritten when a playbook changes.
2. **Optional areas + per-project N/A**
   - On create: include/exclude optional areas (import, ePrescribe, inpatient/MAT, group notes, payroll).
   - On a live project: mark a task or a whole section N/A. That project only — template unchanged. Portal and rollups hide N/A work.
3. **Four playbook paths** on New project
   1. EHR Implementation only
   2. EHR + RCM
   3. Existing EHR + RCM Legacy (No Prism data) — lite plan overview + RCM
   4. Existing EHR + RCM (Yes Prism data) — attach to an existing site, auto-complete overlapping implementation tasks, reactivate, track RCM separately (EHR dates stay put)
4. **Staffing roles** (plus existing customer / lead / contributor / observer)
   - Implementation Specialist, T1/T2 Billing Support, RCM Implementation Specialist, RCM Manager, Implementation Director, Support Director
   - v1.8.1 `SPECIALIST` / `RCM` / `BILLING_SUPPORT` remain valid aliases
   - Tasks auto-assign from the create-project roster; assignment is still editable on the task
   - Managers/directors assigned to a site get a dashboard overview card even if they do not own every task

## Schema — migration `0010_playbook_staffing`

- New enums: `playbook_path`, `work_track`
- `project_member_role` **ADD VALUE** only (no rewrite of existing memberships)
- `user.staffing_role`

- Project: playbook path, source project, RCM start/target, EHR/RCM counters
- Phase/task: `not_applicable`, `work_track`, area/overlap/default role

## Azure migrate

Deploy-to-main already runs `npm run db:migrate` in GitHub Actions.

**Manual / first Azure apply:**

```bash
# DATABASE_URL = Azure Flexible Server connection string
npm run db:migrate
```

Migration file: `drizzle/0010_playbook_staffing.sql` (journal idx 10).

Then refresh playbooks (does **not** send customer invite emails; does **not** rewrite existing project tasks):

```bash
npm run db:seed -- --templates-only
```

Optional, to backfill `staffing_role` on the Outlook roster:

```bash
npm run db:seed:staff-logins
# or
npm run db:seed:prism-import
```

Existing WIP imported projects and demo logins are untouched. N/A defaults to false. Old project member roles stay valid.
