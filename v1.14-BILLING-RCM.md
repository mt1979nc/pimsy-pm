# v1.14 Billing configuration / connected tasks / RCM move

PATH playbook **Billing Configuration** is a separate billing-team tab.
Discovery and Site Configuration keep the customer / implementation copies.
Those rows share a **connect key** so completing (or N/A) one reflects in the
other. On EHR+RCM, overlapping payer / ClaimMD / billing-workflow rows **move**
to the RCM tab instead of staying as disconnected EHR duplicates.

**Version:** 1.14.0 (`APP_VERSION` / `package.json`). **HOLD from live** until
Alexander confirms a templates-only seed + playbook resync window. PATH + Prism
naming unchanged. No PHI.

## What this slice lands

1. **Connected duplicate tasks** — `connect_key` on `template_task` and `task`
   (falls back to `overlap_key`). Completing, reopening, or marking N/A on one
   copy updates every other row on the same project with that key. Staff task
   list and task detail show a Connected badge and links.
2. **Billing Configuration team area** — new INTERNAL tab (Dock eyelid: hidden
   on create). Internal copies of Discovery billing intake (questionnaire +
   spreadsheet) and the Site Configuration **Billing Config** group. Customer
   still fills Discovery; billing specialists work the billing tab.
3. **RCM dedupe/move** — EHR+RCM playbook drops EHR copies of `payer_setup`,
   `claimmd_enrollment`, and `billing_workflow_discovery` and keeps the RCM
   tab rows. Template editor **Move to tab** (including nested subtasks) is
   the in-app path for custom playbooks.
4. **Template seed + migrate** — `0017_connected_tasks`. Re-import playbooks
   with `--templates-only`. Resync inserts the new tab, stamps connect keys,
   copies completion onto new connected rows, and moves RCM-overlap WIP.
5. **Add RCM after create** — staff action on active Implementation WIP
   (Tasks hub + Settings) before Hand-off / COMPLETED / Onboarded. Idempotent
   (already-on, no duplicate tasks). Uses the same RCM_PRISM materialize +
   connect-key logic. Open Billing ↔ Discovery/Config overlap stays connected;
   already-done overlap copies are marked done. Existing billing/RCM members
   are preselected — nobody is invented. Path 4 (new-project attach to an
   existing Prism site) still auto-completes historical overlap.

## Azure Cloud Shell (HOLD — not a live deploy)

No Dock credentials. Copy `DATABASE_URL` from App Service → Configuration.

```bash
export DATABASE_URL='postgresql://…'   # quotes; do not commit
npm ci                                 # if this shell has no node_modules
# apply migration 0017 (connect_key) via the app's usual migrate/deploy path
npm run db:seed -- --templates-only    # rebuild playbooks (not live tasks)
npm run db:resync:playbook-from-dock   # dry-run: insert-phase, insert, set-connect-key, move
npm run db:resync:playbook-from-dock -- --apply
```

`--templates-only` refreshes **template** rows (Billing Configuration,
connect keys, EHR+RCM move). It does **not** rewrite live project tasks.
`--apply` on resync is what backfills existing WIP:

| Resync action | Meaning |
|---------------|---------|
| `insert-phase` | Add **Billing Configuration** (and any other missing tab) |
| `insert` | Add connected copies; copy status/N/A from the existing peer |
| `set-connect-key` | Stamp `connect_key` / `overlap_key` on matching titles |
| `move` | EHR+RCM / RCM_PRISM: overlapping payer / ClaimMD / workflow rows → RCM tab |

Completed / cancelled sites are skipped. User uploads and staff notes are left
alone. Existing WIP is **not** auto-hidden — Billing Configuration starts as a
new INTERNAL tab (staff expose when ready). Completing **Expose the "Billing
Configuration" tab** opens it.

## New workspaces

`materializeTemplatesOnProject` copies connect keys. EHR-only sites get
Discovery + Configuration + Billing Configuration connected triples. EHR+RCM
sites get Billing Configuration intake copies and RCM-owned payer / ClaimMD /
workflow (no EHR duplicate). Path 4 (add RCM to an existing EHR from New
project, Prism history) still auto-completes overlap, then live connect keeps
them in sync.

Mid-implementation **Add RCM** (existing live WIP, a week or two after
create) uses `overlapMode: "connect"`: still-open overlapping work is **not**
marked done. Completing Discovery, Billing Configuration, or the new RCM copy
updates the peers. Available until Hand-off / COMPLETED / Onboarded. A second
Add RCM reports already-on and does not duplicate tasks.

## Client-bundle safety

`src/lib/connected-tasks.ts` and `src/lib/add-rcm.ts` are client-safe (catalog
and Add RCM eligibility only). Status sync lives in
`src/lib/connected-task-sync.ts` and `src/actions/tasks.ts` — not imported
from client components. Task rows receive a `connectedNote` string from the
server page.
