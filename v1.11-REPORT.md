# v1.11 Prism cutover — implementation report

**Date:** 2026-09-14

**Architecture:** Native Postgres in PATH (`pimsy-pm`) is the book of business. **No** Prism Azure SQL dual-write. Dual-read is dump/import CLI only.

**Naming (locked):** **PATH** = Plan · Assign · Track · Handoff (the Dock-replacement app). **Prism** = Portfolio · Readiness · Insight · Staffing · Metrics (analytics module inside PATH). Standalone nice-rock is what we retire.

## What shipped

1. Gap matrix + Azure import/dark runbook + go/no-go checklist — `v1.11-PRISM-CUTOVER.md`
2. One-time import: `npm run db:dump:prism` / `db:import:prism` + Cloud Shell `scripts/azure-cloud-shell-dump.py`. Idempotent by acronym / `prism_team_id`. WIP playbooks and demo logins protected.
3. Daily parity: add-to-roster, pipeline filter, Analysis forecast-vs-actual table, Prism Staffing morning snapshot.
4. Engagement date/hour/status saves revalidate Forecast (weekly load stays in sync).
5. `GET /api/prism/snapshot` for Director / Pipeline / morning routines (`PRISM_READ_API_KEY` or Management session).
6. Chrome: sidebar / sign-in / document title = PATH; Leadership vs Prism nav sections.

## Azure migrate

No new SQL migration. Deploy-to-main already runs `npm run db:migrate`.

Add App Setting `PRISM_READ_API_KEY` (generate; do not invent Prism SQL passwords). Do **not** put `PRISM_SQL_CONNECTION_STRING` on the Web App.

## Go/no-go

See the checklist at the bottom of `v1.11-PRISM-CUTOVER.md`. Darking nice-rock / deleting `pimsy-prism-sql` is a human confirm after the import runs on production.
