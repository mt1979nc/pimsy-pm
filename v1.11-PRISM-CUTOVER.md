## 2. One-time import runbook

The Aug-2026 snapshot (`npm run db:seed:prism-import`) **skips existing acronyms**. Live Prism has likely drifted. Cutover import **updates** by acronym / `prism_team_id`.

### What is imported

| Prism | PATH | Idempotency |
|---|---|---|
| Team (+ Flags JSON, HoursPerWeek) | `user` hours + capacityExempt / canLead / isDirector / prismTeamId | `prism_team_id` then email |
| FormerTeam | `user.isActive=false` when matched | same |
| Customers.Data | project + customer_account + project_scope + slip_event | acronym = `project.code` / `prismClientId` / `crmAcronym` |
| CompletedImplementations | COMPLETED + archived analytics rows | same acronym |

**Never overwritten:** passwords, app roles, playbook tasks/phases, and live
WIP keyed by Prism acronym. Demo logins (`demo.manager@`, Riverbend / `IMP-9001`)
are **not** part of the live book — strip them with `npm run db:cleanup:demo`
(see `azure/README.md`). If Prism says **completed** but PATH still has a WIP
playbook, status is **not** flipped (warning logged).

### A. Dump from Prism SQL (preferred if you can reach it)

Connection string = Prism SWA app setting **`SQL_CONNECTION_STRING`** (server `pimsy-prism-sql.database.windows.net`, database `prism`). **Do not invent credentials.** Do not commit the string.

From a host allowed through the SQL firewall (your laptop with a rule, or Azure Cloud Shell):

```bash
export PRISM_SQL_CONNECTION_STRING='...'   # paste from SWA Configuration
npm install mssql --no-save                # only needed for the Node dump
npm run db:dump:prism -- --out prism-dump.json
```

### B. Azure Cloud Shell (when the cloud agent / CI cannot reach SQL)

1. Portal → Static Web Apps → nice-rock / purple-beach → Configuration → copy `SQL_CONNECTION_STRING`.
2. Cloud Shell, with this repo (or just the `scripts/` folder):

```bash
export PRISM_SQL_CONNECTION_STRING='...'
python3 scripts/azure-cloud-shell-dump.py prism-dump.json
```

(`sqlcmd` must be on the PATH — Cloud Shell usually has it. The script parses Server / User ID / Password from the ADO.NET string and writes canonical JSON.)

3. Copy `prism-dump.json` to a machine that can reach **PATH** Postgres.

### C. Apply into PATH Postgres

```bash
export DATABASE_URL='...'                  # PATH Flexible Server (same secret as GitHub Actions)
npm run db:import:prism -- --dry-run ./prism-dump.json
npm run db:import:prism -- ./prism-dump.json
```

Dry-run prints `insert` / `update` / `protect-wip` / `protect-demo` per acronym. After apply, open **Prism → Forecast** and confirm the book matches standalone Prism.

Historical fallback (does **not** refresh existing rows): `npm run db:seed:prism-import`.

Example dump shape: `scripts/fixtures/prism-dump.example.json`.

## 3. Routines cutover (Director / Pipeline / morning snapshot)

| Old | New |
|---|---|
| Query Prism Azure SQL Team / Customers | `GET https://pimsy-app.azurewebsites.net/api/prism/snapshot` |
| Prism Capacity headroom | `thisWeekHeadroom`, `peakHeadroom`, `hireNow` |
| Pipeline list | `pipeline[]` (off load) |
| Go-lives this/next week | `goLivesNext14[]` |
| Roster | `engagements[]` + `team[]` |

**Auth**

1. App Service setting `PRISM_READ_API_KEY` = `openssl rand -base64 32`
2. Header: `Authorization: Bearer <that key>`
3. Or a signed-in OWNER/ADMIN/MANAGER cookie (browser check)

Power Automate / Copilot: HTTP GET, parse JSON. Optional `?weeks=12`.

**Dual-read:** optional and **CLI-only** (`PRISM_SQL_CONNECTION_STRING` on the dump machine). Runtime pages never merge Prism SQL. `src/lib/prism-dual-read.ts` stays off.

After the import looks right, change each routine in the same sitting. Leave Prism SWA **read-only** for a day if you want a safety net, then dark it.
