# v1.12 Dock parity runbook

PATH workspaces should match **Dock Implementation WIP** for active delivery, plus a clearer customer Learning Center. This is ops for Alexander / Cloud Shell — no invented secrets or Dock credentials.

**Version:** 1.12.0 (`APP_VERSION` / `package.json`)

## What shipped

1. **Prune active non-Dock WIP only** — keep post go-live / completed / archived history.
2. **Task / subtask parity** — nested playbook + resync that does not wipe completion.
3. **Default attachments** — Discovery Wizard, billing sheets (placeholders + admin upload).
4. **Training area checklists** — first-class checkboxes on training tasks.
5. **Learning Center** — portal library grouped by topic (not a Dock-style flat dump).

PATH + Prism naming is unchanged.

## 0. Migrate, then seed catalogs

From a host that can reach PATH Postgres (Azure Cloud Shell or CI):

```bash
export DATABASE_URL='postgresql://…'   # paste from App Service → Configuration. Do not invent.
npm ci                                 # if this shell has no node_modules
npm run db:migrate
npm run db:seed -- --templates-only    # refreshes playbooks + library placeholders + Learning Center
```

`--templates-only` does **not** create demo customers. It **does** upsert Learning Center sections and placeholder files. Uploaded (non-placeholder) library files are kept.

## 1. Prune customers not on current Dock WIP (active book only)

**You must pass an allowlist file.** The live Dock acronym list is not in this repo. Parent supplies JSON/CSV after the Dock scrape.

Accepted shapes:

- JSON array: `["BHC","CEDAR"]`
- `{ "acronyms": ["BHC"] }`
- Dock snapshot: `{ "workspaces": [{ "acronym": "BHC", "name": "…" }] }` (same as `db:import:dock-wip`)
- CSV with an `acronym` column, or one acronym per line

Example (not production): `content/dock-wip-allowlist.example.json`

```bash
# Cloud Shell — DATABASE_URL already exported
npm run db:cleanup:non-dock -- ./dock-wip.json
# review DELETE vs KEEP lists
npm run db:cleanup:non-dock -- ./dock-wip.json --apply
```

### Default rules (locked)

| Keep | Delete |
|------|--------|
| Acronym on the allowlist | Active / pre-kickoff / pipeline / other WIP **not** on the allowlist |
| `status` COMPLETED or CANCELLED | |
| `archivedAt` set | |
| `actualGoLiveDate` in the past | |
| Customer LIVE/CHURNED when the project is not still active WIP | |
| Named staff (alexander@, jeremy@, …) | Portal contacts only when their customer is deleted |

`--keep-prism-analytics` also keeps **pipeline-only** analytics sites that are not on Dock WIP. Default is to prune those with the rest of the active book (completed Prism sites stay).

Prism completed / pipeline-only sites **not** in Dock WIP:

- Completed / actual-end-in-the-past → **kept** (historical Forecast/Analysis).
- Pipeline-only still in the active book → **delete candidates** unless `--keep-prism-analytics`.

The script never deletes playbooks.

### Azure Cloud Shell

1. Azure Portal → App Service → **Settings → Environment variables / Configuration** → copy `DATABASE_URL`.
2. Cloud Shell, repo at v1.12+:

```bash
export DATABASE_URL='postgresql://…'   # quotes; password stays in the variable, not in git
npm ci
# upload or paste the Dock allowlist (from parent), then:

```

Idempotent: a second dry-run should show an empty DELETE list for the active book.

## 2. Resync playbook nested tasks from Dock template

Hypothesis: earlier Dock WIP import could leave a **shallow** task tree if the template lacked `parent_task_id` at import time. Current seed already nests Dock section groups (`G(...)` in `template-implementation.ts`).

```bash
npm run db:seed -- --templates-only          # if not done in step 0
npm run db:resync:playbook-from-dock         # dry-run
npm run db:resync:playbook-from-dock -- --apply
# optional: --only CEDAR,BHC
```

Matching is by **normalized title inside a phase**. Existing DONE / IN_PROGRESS / BLOCKED rows keep status and `completedAt`. Missing nested tasks are inserted as TODO. Missing checklist rows and default files are added. Extra custom tasks are never deleted. **Completed / cancelled projects are skipped.**

After apply, spot-check one WIP site: Kickoff should show Pre-Kickoff → children; Core training should show Training 1 → Schedule / Recording / etc.

If a Dock scrape later shows different titles, update `src/db/template-implementation.ts` and re-run seed + resync (still match-by-title).

## 3. Default attached items (Discovery Wizard, billing sheets)

Placeholders (markdown, no PHI) live in `content/default-attachments/` and seed into the **file library**:

| Slug | Attaches to (task title) |
|------|--------------------------|
| `discovery-wizard` | Guided Discovery Meeting, Organization Details Form, Clinical Workflows, Schedule: Workflow Guided Discovery |
| `billing-spreadsheet` | Complete & Upload Billing Spreadsheet — Accepted Payers, Modifiers |
| `billing-questionnaire` | Billing Questionnaire, Review Billing Questionnaire Data Sheet |
| `clinical-workflows-sheet` | Clinical Workflows, Review Clinical Workflow Data Sheet |
| `organization-details-form` | Organization Details Form |

**Alexander:** in PATH, Owner/Admin → **Templates → File library** (or `/library`). Replace each placeholder with the live Dock file (xlsx/pdf/docx). Storage is the same Azure Blob / `UPLOAD_DIR` pattern as task uploads (`AZURE_STORAGE_CONNECTION_STRING` already used in production). New workspaces copy the current library blob onto matching tasks. Existing WIP gets copies on `db:resync:playbook-from-dock -- --apply` when the attachment is still missing.

Do not commit production binaries or connection strings.

## 4. Training “areas to cover”

If a later Dock scrape includes a sample description with `- [ ]` lines, those parse via `parseChecklistFromDescription` — paste into the task description or we can extend resync to import them. Until then, titles in `src/db/dock-training-checklists.ts` are the curriculum map (logistics only, no PHI).
