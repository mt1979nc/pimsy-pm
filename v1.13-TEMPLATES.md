# v1.13 Template area — Dock playbook copy

PATH playbook **tasks must mirror Dock Implementation**: descriptions (including
training “areas to cover”) **and** attachments, with discovery resources as
**clickable buttons on the task**. Customer upload-request tasks tell the
practice to download, complete, and upload the file back. Existing WIP is
brought into parity with a hang-free Azure resync. Does **not** call the Dock
API or edit live Dock Spaces.

**Version:** 1.13.8 (`APP_VERSION` / `package.json`). v1.13.0–1.13.1 shipped
Dock task action buttons; v1.13.7 file library Link/Form; **v1.13.8** is Dock
eyelid expose/hide + portal links into tasks.

PATH + Prism naming is unchanged. There is no live Dock scrape of per-task
body text in this repo; the source of truth is the in-repo port
(`src/db/template-implementation.ts` titles + `dock-playbook-copy.ts` /
`dock-training-checklists.ts` / `dock-default-attachments.ts`).

## What this slice lands

1. **Dock task action buttons** — Implementation-template tasks that have a
   Dock Task Action (button dependency) show the live PWMI blue CTA on the
   staff and portal **task list** and on **task detail**. Labels and
   destinations (2026-09-15 PWMI screenshots):
   - **Organization Details Form** — **Click Here** opens the Discovery Wizard
     (`https://calm-mud-0fe119810.7.azurestaticapps.net/`) in a popup (Open in
     new tab as fallback). Guided Discovery titles use the same wizard link.
   - **Clinical Workflows** — **Click Here to Submit Clinical Workflow Form**
     (Dock Form; PATH opens the playbook sheet when attached — no public Dock
     form URL in this repo).
   - **Billing Questionnaire** — **Click Here to Submit Billing Questionnaire**
     (same Form fallback).
   - **Complete & Upload Billing Spreadsheet**, Submit Documents, logos,
     letterhead — **Upload files**.
   - **Documentation & Forms** — **Open form**.
   Not only Open/Download chips in Links & files. No invented Storylane or
   booking URLs.
2. **Download → complete → upload** — customer upload-request tasks (RCM
   intake, file requests) instruct the practice to complete the work and
   upload the finished file back on this task. Billing spreadsheet uses
   **Upload files**. Specialist review / Guided Discovery stay open-or-review
   only.
3. **Descriptions match Dock** — training tasks get the session blurb plus
   `- [ ]` lines for each area to cover (Training 1 also notes Storylane as a
   LINK attachment, **no invented URL**). URLs stay on attachments, not in the
   body. Wizard tasks say Click Here opens the Discovery Wizard. Clinical /
   Billing form tasks use the PWMI form labels.
4. **Attachments match Dock** — Discovery Wizard LINK, billing spreadsheet and
   questionnaire, clinical workflows sheet, organization details form, RCM
   intake. Upserted onto the playbook; cloned onto live tasks. Title aliases
   include Dock names like “Discovery org details”. Clinical Workflows no
   longer auto-attaches the wizard LINK (Dock Form, not the wizard).
5. **Existing PATH playbooks** — `db:resync:playbook-from-dock` dry-run then
   `--apply` backfills blank/stale descriptions (including v1.13 Open/Download
   blurbs), missing checklist rows, and missing default files. **The PWMI CTA
   still appears from the task title before resync.** Staff-authored notes
   and user uploads are left alone.
6. **New workspaces** inherit template descriptions + checklists + default
   files automatically (`materializeTemplatesOnProject`). Buttons resolve
   from title on every new site.
7. Editor / duplicate / optional-areas / hub nav from the first v1.13 slice
   stay; they are not the priority.

## Azure Cloud Shell (resync)

No Dock credentials. Copy `DATABASE_URL` from App Service → Configuration.

```bash
export DATABASE_URL='postgresql://…'   # quotes; do not commit
npm ci                                 # if this shell has no node_modules
npm run db:seed -- --templates-only    # rebuild playbooks + extras (not live tasks)
npm run db:resync:playbook-from-dock   # dry-run; prints [Ns] progress
npm run db:resync:playbook-from-dock -- --apply
```

`--templates-only` refreshes **template** rows (descriptions, checklists,
default files). It does **not** rewrite live project tasks. `--apply` on
resync is what backfills existing WIP. `--apply` also refreshes catalogs
first (batched upsert; does not wipe editor extras).

Useful flags:

| Flag | Meaning |
|------|---------|
| `--only CEDAR,BHC` | One or more acronyms / codes / ids |
| `--limit 5` | First N eligible WIP projects |
| `--timeout-sec 120` | Stop instead of hanging (default **180**) |
| `--timeout-sec 0` | No cap |
| `--seed` | Refresh catalogs even on dry-run |
| `--apply` | Write live tasks (also refreshes catalogs) |

If a previous dry-run sat silent: that was per-task N+1 queries. This version
batch-loads extras, logs every project, and exits with a partial plan +
`TIMED OUT` rather than spinning. Re-run with `--only` for remaining codes.
Completed / cancelled sites are skipped. User uploads are never deleted.
Blank or stale training blurbs are filled; custom notes are not.
