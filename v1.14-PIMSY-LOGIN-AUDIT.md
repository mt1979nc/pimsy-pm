## Real integration path

1. Expose a **read-only HTTPS** endpoint that returns **login/session** events for one site (no patient/chart rows).
2. Set App Settings on the PATH Web App (`pimsy-app`):

   ```
   PIMSY_AUDIT_FEED_URL=https://…/logins
   PIMSY_AUDIT_FEED_TOKEN=…          # optional Bearer
   PIMSY_AUDIT_FEED_WINDOW_DAYS=14   # optional, max 90
   ```

   Path placeholders `{siteKey}` and `{crmKey}` are substituted. PATH also sends query params `siteKey`, `crmKey`, `since` (ISO), `windowDays`.

   `siteKey` = project `crmAcronym` else `prismClientId` else `code` (About). Fill those before expecting a match.

3. JSON body (any of: `{ "sessions": [...] }`, `{ "logins": [...] }`, or a top-level array). Each row:

   | Field | Also accepted | Required |
   |-------|----------------|----------|
   | `displayName` | `name`, `fullName`, `user` | name **or** username |
   | `username` | `userName`, `login`, `email` | name **or** username |
   | `loggedInAt` | `loginAt`, `startedAt`, `loginTime`, `timestamp` | yes (ISO) |
   | `loggedOutAt` | `logoutAt`, `endedAt`, `logoutTime` | no |
   | `durationSeconds` | `durationMinutes`, `duration` as `HH:MM:SS` or `45m` | no (computed from in/out when missing) |
   | `eventType` | `event`, `action`, `type` | if present, must be a login/session |

   Rows with patient/MRN/chart/diagnosis keys are dropped. Non-login event types are dropped. PATH **does not persist** feed rows.

4. Redeploy is not required for App Settings; restart the Web App after saving. Confirm on a Training 1 confirm-logins task for a site with a real acronym (e.g. THS).
